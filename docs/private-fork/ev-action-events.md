# EV command and failed-stop events

Adapted from upstream `f1ab528fcf9b095ae3ef0ffa58639b5e6c656774` for the private shared Generic/Sigenergy EVAC loadpoint. This port does **not** add Tesla/Zaptec observers or optimizer events.

`power_sync_ev_command` reports a recorded command result. Its payload contains `schema_version: 1`, `entry_id`, `vehicle_id`, `command`, `timestamp`, `source`, `success`, `reason`, `record_type`, `physical_confirmation` and `observed_at`. `vehicle_id` is the existing ownership/command ID: shared A/B commands use the same canonical physical ID (`generic_ev` or `sigenergy_charger`), not the logical profile. A successful command acknowledgement is **not** confirmation that charging stopped.

`power_sync_ev_stop_failed` reports the first unresolved PowerSync stop failure for an entry/loadpoint and creates a persistent HA warning. Further failed stops on that physical loadpoint are deduplicated. A successful retry does not clear the warning. A fresh physical idle observation *captured after the latest stop* by the selected shared Generic/EVAC reconciler publishes `stop_observed` with `physical_confirmation: true` and dismisses the warning. EVAC requires both a stopped state and measured power at or below 50 W; stale, unknown, unmapped-selector, or positive-power observations cannot do so. This observation does not release a physical lease, retag a session, or issue another charger command. For other backends in this focused port, no new telemetry observer is installed; a warning can be dismissed manually in HA and the runtime latch resets on restart.

A failed stop means **not confirmed**, not proof of ongoing charging. Check actual charger power and the home battery. To send phone alerts, configure a Home Assistant event automation listening for `power_sync_ev_stop_failed`; this port does not send a new phone notification automatically.
